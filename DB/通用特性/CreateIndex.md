# Index 建立原則與建議

1. 索引的設計流程

+ Step 1. 先根據需求，來判斷可能需要建索引的欄位
首先第一件事情就是定義需求或是預測，來決定那些欄位『 可能 』需要建立索引，等有候選欄位後在進行下一個步驟。

+ Step 2. 看看候選欄位的基數大小
基數就是指這個欄位的值的可能性。
像假設某個欄位是存性別，也就是說只有『 男 』與『 女 』，那就代表這個欄位基數很小，這時就不建議建立索引。

+ Step 3. 決定使用的索引類型
基本上就是以下三種選擇 :

  + 一般索引(覆蓋索引) : 在一些常用單獨 query，如果需要與其它欄位一起查詢，可考慮建連合索引。

  + 聯合索引 : 常常需要與其它欄位一起查詢，適合建立。但是要注意先後順序，基本最常查詢的與基數高的適合放最左邊。

  + 唯一索引 : 這種適合欄位值是唯一的，它可以順到幫你檢查是不是唯一。

1. 建議

在 MySQL 中建立索引時，有一些建議可以幫助你優化查詢性能和減少資源消耗

+ 選擇合適的列：選擇經常用於查詢條件的列來建立索引。通常情況下，頻繁用於 WHERE 子句、JOIN 子句和 ORDER BY 子句的列是最適合建立索引的列。

+ 避免過多索引：不要為每個列都建立索引，因為過多的索引會增加維護成本、降低寫入性能，並且會消耗更多的存儲空間。只建立必要的索引以滿足查詢需求。

+ 考慮複合索引：如果查詢涉及多個列，可以考慮建立複合索引。複合索引可以提高多列查詢的性能，並且通常比單列索引更有效。

+ 避免在頻繁更新的列上建立索引：頻繁更新的列上的索引會增加寫入操作的成本。在這種情況下，需要權衡查詢性能和寫入性能，確保索引的收益大於成本。

+ 瞭解索引類型：MySQL 支援多種類型的索引，包括 B-Tree 索引、雜湊索引、全文索引等。瞭解每種索引類型的特點和適用場景，選擇最合適的索引類型。

+ 使用 EXPLAIN 分析查詢計畫：使用 EXPLAIN 命令分析查詢語句的執行計畫，瞭解 MySQL 如何使用索引來執行查詢，優化查詢語句和索引設計。
