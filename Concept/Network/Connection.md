# Connection Induction

## HTTP（Hypertext Transfer Protocol）

用於在 Web 上傳輸超文本的應用層協定。

## HTTPS（HTTP Secure）

是基於 HTTP 的安全通訊協定，透過使用 TLS/SSL 加密傳輸數據，確保了通訊過程的安全性。

## TLS/SSL 原理

+ **握手階段（Handshake）**：在通訊雙方建立連線之前，客戶端和伺服器之間會進行握手協商，更新加密演算法、金鑰長度等參數。
  + 客戶端向伺服器發送握手請求，請求建立安全連線。
  + 伺服器回應握手請求，並返回伺服器證書，證明伺服器的身分。
  + 客戶端驗證伺服器證書，並生成用於加密通訊的隨機數，並使用伺服器的公鑰加密該隨機數。
  + 伺服器收到客戶端的隨機數，並使用自己的私鑰解密，獲取客戶端生成的隨機數，並生成用於加密通訊的金鑰。
  + 客戶端和伺服器使用協商好的加密演算法和金鑰，開始安全傳輸數據。

+ **加密通訊階段（Secure Communication）**： 客戶端和伺服器之間的數據傳輸透過加密通道進行。在握手階段協商好的加密演算法和金鑰用於對數據進行加密和解密，以確保數據在傳輸過程中的機密性和完整性。

+ **斷開連線階段（Connection Termination）**： 通訊結束時，客戶端和伺服器會發送關閉連線的訊息，並釋放資源。在 TLS/SSL 中，通常會透過關閉握手協定來終止連線，以確保最後一條訊息的安全。

## SSH（Secure Shell）

是一種用於在網路上安全登入遠端電腦並執行指令的協定。它提供了加密的數據通訊，防止了數據洩漏和中間人攻擊。

## SMTP（Simple Mail Transfer Protocol）

用於在網路上傳輸電子郵件的協定。它定義了電子郵件的傳輸規則和格式，負責將電子郵件從發送方傳輸到接收方的郵件伺服器。

## TCP vs UDP

+ **TCP（傳輸控制協定）**：
  + 可靠性： TCP 提供可靠的數據傳輸，透過使用確認、重傳和流量控制等機制來確保數據的可靠傳輸。
  + 有序性： TCP 保證封包的有序傳輸，接收端會按照發送端的順序重新組裝封包。
  + 連線導向： TCP 是一種面向連線的協定，通訊雙方需要在數據傳輸之前建立連線，並在傳輸完成後釋放連線。
  + 流式傳輸： TCP 提供面向流的數據傳輸，將數據視為連續的位元組流進行傳輸。
  + 適用性： 適用於需要可靠傳輸、有序傳輸和連線導向的應用，如網頁瀏覽、檔案傳輸等。
+ **UDP（用戶資料報協定）**：
  + 簡單性： UDP 是一種簡單的、無連線的協定，不需要建立連線和維護狀態，通訊雙方可以直接進行數據傳輸。
  + 無序性： UDP 不保證封包的順序傳輸，接收端收到封包的順序可能與發送端不一致。
  + 不可靠性： UDP 不提供數據傳輸的可靠性，封包可能會遺失、重複或亂序，接收端需要自行處理。
  + 資料報式傳輸： UDP 使用資料報形式進行傳輸，每個封包都是獨立的，不依賴於其他封包的狀態。
  + 適用性： 適用於對即時性要求高、數據量小、可以容忍少量遺失的應用，如音訊視訊串流傳輸、線上遊戲等。

## TCP 握手

1. **第一次握手（SYN）**：
   客戶端向伺服器發送一個 SYN（同步）封包，表示客戶端請求建立連線。
   客戶端選擇一個隨機的序號（SeqNum）作為起始值，並發送 SYN 包。
2. **第二次握手（SYN-ACK）**：
   伺服器收到客戶端發送的 SYN 包後，會向客戶端發送一個 SYN-ACK 包。
   伺服器確認了客戶端的請求，並選擇一個隨機的序號作為伺服器的起始值，並發送 SYN-ACK 包給客戶端。
3. **第三次握手（ACK）**：
   客戶端收到伺服器發送的 SYN-ACK 包後，會向伺服器發送一個確認包 ACK。
   客戶端也確認了伺服器的請求，並將伺服器的序號加一作為客戶端的起始值，並發送 ACK 包給伺服器。

## TCP 揮手

+ **第一次揮手（FIN）**：
  客戶端或伺服器端的一方發送一個 FIN（結束）封包，表示自己不再有數據要發送了，但仍然可以接收數據。
  發送 FIN 封包的一方進入「半關閉」狀態，即該方向的數據傳輸已經結束，但仍然可以接收對方發送的數據。

+ **第二次揮手（ACK）**：
  接收到 FIN 封包的一方向對方發送一個 ACK（確認）封包，表示已經收到了 FIN 封包，並進入「等待關閉」狀態。此時該方向上的數據傳輸仍然可以繼續進行，但無法再向對方發送數據。

+ **第三次揮手（FIN）**：
  接收到 ACK 封包的一方，在數據傳輸結束後也向對方發送一個 FIN 封包，表示自己也不再有數據要發送了，並請求關閉連線。發送 FIN 封包的一方也進入「半關閉」狀態，等待對方發送 ACK 封包。

+ **第四次揮手（ACK）**：
  接收到 FIN 封包的一方向對方發送一個 ACK 封包，表示已經收到了對方發送的 FIN 封包，並確認關閉連線。
  此時連線的關閉已經完成，雙方的連線狀態都變為「已關閉」。
