# CORS 相關問題

## 簡介

跨域問題（Cross-Origin Resource Sharing，CORS）是指在瀏覽器中運行的前端程式碼（例如 JavaScript）試圖從不同的來源（域、協定或連接埠）載入資源時遇到的安全限制。當網頁試圖透過 AJAX 請求來自不同來源的資源時，瀏覽器會執行同源策略（Same-Origin Policy），限制跨源請求。

同源策略的主要目的是防止惡意網站獲取使用者的敏感資訊，保護使用者隱私和安全。但在一些情況下，合法的跨域請求是必要的，例如前端應用需要與後端 API 進行通訊，而 API 位於不同的網域名稱下。跨域問題通常表現為瀏覽器在控制台中報錯，攔截跨域請求，導致請求失敗或部分內容無法正常載入。

## 解決方法

+ **在後端伺服器上設置 CORS 標頭**： 後端伺服器可以在回應中添加 CORS 標頭來允許跨域請求。最常見的 CORS 標頭是 `Access-Control-Allow-Origin`，它指定了允許存取資源的網域名稱。您可以將其設置為特定的網域名稱或萬用字元 `*` 表示允許所有網域名稱存取。例如，在 Express.js 中，您可以使用 `cors` 中間件來方便地處理 CORS。

+ **CORS 中間件**： 在一些 Web 框架中，提供了可以用於處理 CORS 的中間件。您可以在應用中添加這些中間件來處理跨域請求。例如，Express 框架中的 `cors` 中間件。

+ **使用代理伺服器**： 在同源伺服器上部署一個代理伺服器，用於轉發跨域請求。前端程式碼發送請求給代理伺服器，代理伺服器再將請求發送給目標伺服器，並將回應返回給前端。這樣，前端請求的是同源伺服器上的資源，避免了跨域問題。

+ **JSONP（僅限 GET 請求）**： 如果您的介面支援 JSONP，您可以使用 JSONP 來解決跨域問題。JSONP 利用 `<script>` 標籤不受同源策略限制的特性，透過動態建立 `<script>` 標籤來載入跨域資源。但 JSONP 只支援 GET 請求，且存在安全風險，需要謹慎使用。
