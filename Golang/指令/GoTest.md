# Go Test 測試指南

針對 CI 環境下的 Go 測試最佳實踐。

---

## 1. 基礎測試指令

### 單元測試

```bash
go test ./...
```

---

## 2. 常用參數 (Flags) 詳細說明

| 參數            | 作用                                                        | 使用時機                                     |
| :-------------- | :---------------------------------------------------------- | :------------------------------------------- |
| **`-v`**        | **Verbose**。印出所有測試案例的名稱與 `t.Log` 輸出。        | 除錯或在 CI 中查看詳細過程時。               |
| **`-race`**     | **Race Detector**。偵測多執行緒競爭問題。                   | **CI 流程必開**，確保並行邏輯正確。          |
| **`-count=1`**  | **停用快取**。強制重新執行測試而不使用上次的結果。          | 當環境變動但程式碼沒變，需要重新驗證時。     |
| **`-timeout`**  | **設定超時**（預設 10m）。若超過時間則判定失敗。            | 整合測試或 E2E 測試，例如 `-timeout 30m`。   |
| **`-run`**      | **執行特定測試**。支援正規表示法。                          | 只想跑某一條測試時，如 `-run ^TestLogin$`。  |
| **`-p`**        | **並行套件數**。限制同時編譯與測試的 package 數量。         | 資料庫測試需循序執行時設為 `-p 1`。          |
| **`-parallel`** | **並行測試數**。限制單一 package 內 `t.Parallel()` 的數量。 | 控制單機測試時的資源消耗。                   |
| **`-short`**    | **短測試模式**。配合 `testing.Short()` 跳過耗時測試。       | 本地開發想快速驗證邏輯時。                   |
| **`-tags`**     | **編譯標籤**。只編譯與執行帶有特定標籤的檔案。              | 區分 `unit`, `integration`, `e2e` 測試環境。 |
| **`-gcflags`**  | **編譯器參數**。傳遞參數給編譯器（如禁用內聯）。            | 進行 Monkey Patch 測試時必開。               |

### 覆蓋率相關參數

* **`-cover`**：開啟代碼覆蓋率分析。
* **`-coverprofile=file.out`**：將覆蓋率結果輸出到檔案。
* **`-coverpkg=./...`**：計算覆蓋率時包含所有 package，而不僅是當前測試的 package。

## 3. 進階技巧

### A. 處理資料庫與整合測試

* **順序執行 (`-p 1`)**：當多個測試同時操作同一個資料庫實例時，並行執行會導致資料污染。使用 `-p 1` 強制測試按順序執行。
* **Build Tags 隔離**：
  * `go test -tags=integration ./...`：將耗時或依賴外部環境的測試標記為 `integration`，避免在一般單元測試時執行。
* **TestMain 模式**：
  * 在 E2E 測試中，利用 `TestMain` 自動執行編譯、啟動服務、等待就緒、執行測試並在最後優雅關閉。

### B. 覆蓋率 (Coverage) 最佳化

* **跨包統計 (`-coverpkg=./...`)**：預設測試只計算當前 package。如果要測 A package 對 B package 的邏輯覆蓋，必須加上此參數。
* **排除產出物**：使用 `grep` 排除 `mock/`、`proto/` 或 `cmd/` 等自動生成的程式碼，避免它們稀釋了真實的業務邏輯覆蓋率。

```bash
go test -coverprofile=.coverage.tmp.txt ./...
grep -vE "/mock/|/cmd/" .coverage.tmp.txt > .coverage.txt
go tool cover -func=.coverage.txt
```

### C. 禁用內聯與 Monkey Patch

在使用像 `monkey` 這種透過修改函式指標（Function Pointer）來替換邏輯的套件時，必須禁用編譯器的 **內聯優化 (Inlining)**。

* **原因**：如果函式被編譯器直接嵌入 (Inlined) 到呼叫端，修改原函式的入口點將無法影響已嵌入的程式碼，導致 Hook 失效。
* **常用參數**：
  * `-gcflags="all=-l"`：禁用內聯 (Lowercase L)。
  * `-gcflags="all=-N -l"`：禁用優化 (`-N`) 與內聯 (`-l`)，這是最保險且最常用的偵錯/測試配置。
* **指令範例**：
  
  ```bash
    go test -gcflags="all=-l" ./...
  ```

## 4. 附錄：常用 -gcflags 選項

`-gcflags` 用於將參數傳遞給 Go 編譯器 (`go tool compile`)。

| 選項        | 作用                     | 說明                                             |
| :---------- | :----------------------- | :----------------------------------------------- |
| **`-l`**    | 禁用內聯 (Inlining)      | **Monkey Patch 必備**。防止函式被嵌入呼叫端。    |
| **`-N`**    | 禁用優化 (Optimizations) | 使偵錯時的變數值與程式碼行號精確對應。           |
| **`-m`**    | 輸出優化決策             | 顯示 **逃逸分析 (Escape Analysis)** 與內聯決策。 |
| **`-m -m`** | 更詳細的優化決策         | 顯示編譯器推導的詳細過程。                       |
| **`-S`**    | 輸出組合語言             | 查看編譯後的機器碼對應。                         |

### 指令範例

* **徹底禁用優化進行測試**：
  
  ```bash
  go test -gcflags="all=-N -l" ./...
  ```

* **分析變數是否逃逸到堆積 (Heap)**：

  ```bash
  go build -gcflags="-m" .
  ```
