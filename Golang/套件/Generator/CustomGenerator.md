# 撰寫自定義的代碼生成器

當現有的工具無法滿足需求時，我們可以撰寫自己的 Go 程式來生成代碼。

## 1. 核心流程

1. **解析源代碼 (Parsing)**：使用 `go/ast`, `go/parser`, `go/token` 等標準庫來解析專案中的抽象語法樹 (AST)。
2. **提取元資料**：找出特定標記的結構體、介面或註解。
3. **範本填充 (Templating)**：使用 `text/template` 將資料填充進預先定義好的代碼模板中。
4. **輸出檔案**：將生成的內容寫入 `.go` 檔案，並使用 `go/format` 進行代碼格式化。

---

## 2. 簡單範例：生成檔案資訊

建立一個 `gen.go`：

```go
package main

import (
    "os"
    "text/template"
)

const temp = `
package {{.PkgName}}

func GetInfo() string {
    return "This file is generated in package {{.PkgName}}"
}
`

func main() {
    pkgName := os.Getenv("GOPACKAGE") // 從 go generate 環境變數取得包名
    f, _ := os.Create("info_gen.go")
    defer f.Close()

    t := template.Must(template.New("info").Parse(temp))
    t.Execute(f, map[string]string{"PkgName": pkgName})
}
```

在業務代碼中使用：

```go
//go:generate go run gen.go
package main
```

---

## 3. go generate 的環境變數

當 `go generate` 執行你的程式時，會注入以下環境變數供你使用：

- **$GOARCH**：目標架構。
- **$GOOS**：目標作業系統。
- **$GOFILE**：包含 `//go:generate` 指令的文件名稱。
- **$GOLINE**：該指令所在的行號。
- **$GOPACKAGE**：該檔案所屬的 Package 名稱。

---

## 4. 推薦的設計模式

- **支援 CLI 參數**：使用 `flag` 套件讓生成器更具彈性。
- **提供多種輸出路徑**：讓使用者決定生成的代碼放在哪裡。
- **明確的標頭**：在生成的檔案頂部加入 `// Code generated by ...; DO NOT EDIT.`，避免人為誤改。
- **自動格式化**：在寫入檔案前呼叫 `format.Source()`，確保生成的代碼符合 Go 的格式規範。
