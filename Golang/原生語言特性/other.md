# 其他特性

## make/new 區別

- make :用於創建和初始化特定類型的集合類型：slice（切片）、map（映射）和 channel（通道），返回的是這些類型的具體值（而不是指針）。

  ```go
  make(type, size, capacity)
  ```

  - type：要創建的集合類型（slice、map 或 channel）。
  - size：初始大小（僅適用於切片和通道）。
  - capacity：切片的容量（可選，若不指定則與 size 相同）。

- new: 用於分配內存空間，但不初始化（僅設為零值）。返回的是分配類型的指針。
  ```go
  new(type)
  ```

  - 用於分配內存空間，但不初始化（僅設為零值）。
  - 返回的是分配類型的指針。
  - 通常用於分配結構體或基本類型的內存空間。

## slice/array 區別

- introduction

  | 特點     | Array（數組）                    | Slice（切片）                         |
  | -------- | -------------------------------- | ------------------------------------- |
  | 長度     | 固定，無法改變                   | 動態，可增長或縮小                    |
  | 定義方式 | var a [5]int                     | var s []int 或 make([]int, size, cap) |
  | 內存分配 | 靜態分配，直接包含數據           | 動態分配，指向底層數組                |
  | 性能     | 比切片稍快，因為沒有額外的元數據 | 性能略低，因為有指針和元數據的管理    |
  | 拷貝行為 | 值拷貝，會創建一份完整的副本     | 引用拷貝，共享底層數據                |

- 常見誤區
  - 切片不是數組的指針：切片是基於數組的引用，底層結構是一個含有三個欄位的結構體（`Data` 指向底層數組的指標、`Len` 長度、`Cap` 容量）。
  - 切片超出容量會重新分配內存：當 `append` 超出原有容量時，Go 會分配一塊新的、更大的記憶體，將舊資料複製過去，並指向新數組。
  * **Go 1.18+ 擴容公式**：
    - 當新申請容量大於雙倍舊容量時，以新申請容量為準。
    - 否則：
      - 若舊容量 `< 256`：容量翻倍 (`new_cap = old_cap * 2`)。
      - 若舊容量 `≥ 256`：每次增加 `(old_cap + 3 * 256) / 4`，直到大於等於所需容量。這使得擴容更平滑，避免了舊版本在 1024 臨界點突然從雙倍降到 1.25 倍的斷崖式設計。

## map

- key 數值類型: 必須是可比較的，比如 int, string, \*T（因為需要透過 `==` 判斷鍵是否相等）。
- map使用的注意点
  - key的唯一性
  - key的不可變性：作為key的類型必須是可比較的，這通常意味著它們應該是不可變的。例如，在Go語言中，切片、映射和函數類型因為包含可變狀態，所以不能直接作為map的key。
  - 初始化和 nil map：在Go語言中，宣告一個 map 變數不會自動初始化它。未初始化的 map 變數的零值是 nil，對 nil map 進行讀操作會回傳零值與 false，但寫操作會引發 panic。因此，在使用 map 之前，必須使用 make 函數或字面量進行初始化。
  - 遍歷順序：如果你需要按照特定的順序處理map中的元素，你應該先將key提取到一個切片中，對切片進行排序，然後按照排序後的順序遍歷切片，並從 map 中取出對應的值。
  - 并发安全性：默认情况下，map并不是并发安全的，併發讀寫會直接引發 fatal error (panic)。在併發場景下需使用 `sync.Mutex` 加鎖，或使用 `sync.Map`。
- 可以用 map[T]struct{} 模擬 set（相比 `map[T]interface{}` 更省空間，因為 `struct{}` 佔用 0 位元組的記憶體）。

### map 底層與隨機遍歷原理

- **底層結構**：
  Go 的 map 底層是哈希表，核心結構體是 `hmap`。`hmap` 中包含一個或多個桶（Bucket，底層為 `bmap` 結構）。每個桶最多可以儲存 8 個鍵值對 (key-value pairs)。當多個 key 的哈希值落到同一個桶且桶滿了時，會透過 `overflow` 指針指向一個溢出桶（即拉鍊法解決哈希衝突）。
- **為什麼遍歷 map 是隨機的？**：
  1. **設計意圖**：Go 官方不希望開發者依賴 map 的遍歷順序。因為當 map 擴容時（由於負載因子過大或溢出桶過多），元素會被重新分配（evacuation）到新的桶中，遍歷順序自然會改變。
  2. **實作方式**：在 `for range map` 時，Go 運行時在初始化迭代器時會調用 `mapiterinit`，在其中**隨機選擇**一個桶的編號，並在該桶內**隨機選擇**一個偏移量作為遍歷起點。即使 map 內容完全不變，每次遍歷輸出的順序依然會不同。
