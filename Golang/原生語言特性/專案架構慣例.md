# Go 專案架構與開發規範

本文件記錄 Go 語言開發中的標準專案佈局慣例以及常見的開發規範。

---

## 1. 標準專案佈局 (Standard Go Project Layout)

Go 社群廣泛認可的目錄結構設計，旨在提高代碼的可維護性與可讀性。

### 核心目錄

| 目錄            | 用途     | 說明                                                     |
| :-------------- | :------- | :------------------------------------------------------- |
| **`/cmd`**      | 進入點   | 每個子目錄代表一個可執行檔。例如 `/cmd/server/main.go`。 |
| **`/internal`** | 私有代碼 | 存放不對外暴露的業務邏輯，Go 編譯器會強制執行存取限制。  |
| **`/pkg`**      | 公共庫   | 可供外部專案引用的程式碼（如果該專案同時作為庫使用）。   |
| **`/api`**      | 接口定義 | 存放 OpenAPI, Proto 檔案及其生成的代碼。                 |

### 輔助目錄

* **`/configs`**：存放 YAML, TOML 等設定檔範本。
* **`/scripts`**：存放編譯、測試或 CI/CD 相關的腳本。
* **`/build`**：存放 Dockerfile 或容器打包配置。
* **`/deployments`**：存放 Kubernetes 或部署平台相關配置。
* **`/test`**：存放整合測試或外部測試資料。

## 2. 文件規範與 Linting (Markdown)

在撰寫開發文件時，應遵守 Markdown 規範以確保在不同編輯器中的顯示一致性。

### MD007: 無序列表縮排 (ul-indent)

**規範要求：**
子項目的縮排建議使用 **2 個空格**。

* **正確範例：**

  ```markdown
  + 父項目
    + 子項目 (2格縮排)
  ```
  
* **錯誤範例：**

  ```markdown
  + 父項目
      + 子項目 (4格縮排，會觸發 MD007 錯誤)
  ```

---

## 3. 開發建議

1. **保持 `/cmd` 簡潔**：僅進行初始化，將邏輯移動到 `internal` 或 `pkg`。
2. **善用 `internal`**：除非確定要開放給他人使用，否則程式碼應優先放在 `internal` 下。
3. **單元測試**：測試檔案 (`*_test.go`) 應與被測試的源碼放在同一個資料夾。
