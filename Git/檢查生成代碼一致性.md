# 檢查生成的程式碼與原始碼一致性

在 Go 或 Protobuf 開發中，常會遇到「修改了定義，卻忘了執行 `go generate` 或 `mockgen` 就提交程式碼」的情況。這會導致遠端代碼庫的產出物與原始碼不一致。

以下是三種主流的解決方案：

---

## 1. CI 流程檢查 (最可靠)

這是目前最推薦的做法。在 CI (GitHub Actions, GitLab CI, Jenkins) 的測試步驟中加入一致性檢查。

### 原理

在 CI 環境中手動觸發一次生成指令，然後檢查 Git 工作區是否有任何變動。

### 指令範例 (以 Go 為例)

```bash
# 1. 執行生成指令
go generate ./...

# 2. 檢查是否有檔案變動
# --exit-code 會讓指令在有差異時回傳非 0 的狀態碼 (通常是 1)
git diff --exit-code
```

### GitHub Actions 範例

```yaml
jobs:
  check-gen:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Run Generate
        run: go generate ./...
      - name: Check for changes
        run: |
          if ! git diff --exit-code; then
            echo "錯誤：生成的程式碼與原始碼不一致，請在本地執行 go generate 並提交變動。"
            exit 1
          fi
```

---

## 2. Pre-commit Hook (本地自動化)

如果你希望在本地 `git commit` 時就被擋下來，可以使用 Git Hook。

### 設定方式

在專案根目錄的 `.git/hooks/pre-commit` 加入以下內容：

```bash
#!/bin/sh
go generate ./...
git diff --exit-code > /dev/null
if [ $? -ne 0 ]; then
    echo "偵測到生成的程式碼過期，請將變動加入 stage 後再 commit。"
    exit 1
fi
```

*註：建議使用 `pre-commit` 框架 (pre-commit.com) 來管理，更易於團隊共享。*

---

## 3. 核心工具指令說明

### `git diff --exit-code`

這是達成此功能的關鍵指令：

- **回傳值 0**：表示目前工作區與 HEAD 沒有差異（代碼已是最新的）。
- **回傳值 1**：表示有差異（代表你忘了跑生成指令，或者跑完後檔案變了）。

### `git status --porcelain`

如果你只想檢查是否有「未追蹤 (Untracked)」的新檔案生成：

```bash
if [ -n "$(git status --porcelain)" ]; then
  echo "工作區不乾淨"
  exit 1
fi
```

---

## 總結建議

1. **開發規範**：團隊應養成「先 generate，再 test，最後 commit」的習慣。
2. **自動化防線**：**一定要在 CI 中加入 `git diff --exit-code` 檢查**，這是防止錯誤進入主幹分支的最強手段。
